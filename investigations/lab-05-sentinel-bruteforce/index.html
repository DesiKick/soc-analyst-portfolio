    Lab 05: Windows Authentication & Brute Force Detection in Microsoft Sentinel (KQL)¶

    Category: Cloud SIEM & Identity Detection Engineering
    MITRE ATT&CK: T1110.001 Password Guessing • T1110.003 Password Spraying • T1059.003 Command & Scripting Interpreter
    Platform: Microsoft Sentinel / Azure Log Analytics Workspace
    Telemetry Agent: Azure Monitor Agent (AMA) / Windows Security Event Log
    Rule Format: Kusto Query Language (KQL) Analytic Rule

    Incident Verdict: True Positive — High Severity — Identity Compromised

    Target workstation FIN-WKSTN-04 sustained 142 consecutive network authentication failures (Event ID 4625, SubStatus 0xC000006A) within a 12-minute window originating from internal IP 192.168.10.45. The attack culminated in a single successful logon (Event ID 4624) under domain account CORP\jdoe, followed immediately by suspicious discovery command execution (whoami /all). Immediate host containment, session termination, and credential revocation were executed.

    1. Executive Summary & Forensic Artifacts¶

    During continuous security monitoring in Microsoft Sentinel, analytics detected an anomalous spike in SMB network authentications targeting a high-value finance workstation. Investigation confirmed an adversary executed an automated dictionary brute-force attack against local Active Directory credentials.

    Forensic Telemetry Breakdown¶

    2. Windows Authentication Mechanics & Telemetry Deep-Dive¶

    Windows audit logging generates distinct Event IDs for authentication attempts. Differentiating benign user error from brute force requires parsing the raw XML event data.

    Relevant Windows Event IDs¶

    • Event ID 4625 (An account failed to log on): Generated on the system where the logon attempt occurred. Provides source IP, target account, and the exact NTSTATUS failure code.
    • Event ID 4624 (An account successfully logged on): Generated upon successful authentication. Critical for identifying whether an adversary guessed the password.
    • Event ID 4688 (A new process has been created): Captures post-compromise activity if command-line process auditing is active.

    Diagnostic NTSTATUS Hex Codes (Event ID 4625)¶

    The SubStatus field is the primary indicator of adversary intent:

    SubStatus Code NTSTATUS Macro Root Cause Analysis Analyst Interpretation
    0xC000006A STATUS_WRONG_PASSWORD Account exists; password incorrect. Primary indicator of brute force / password guessing.
    0xC000006D STATUS_LOGON_FAILURE General authentication error. Typically accompanies bad credentials or mismatched domains.
    0xC0000064 STATUS_NO_SUCH_USER The specified user does not exist. Indicator of user enumeration or spraying unverified lists.
    0xC0000072 STATUS_ACCOUNT_DISABLED Account is administratively disabled. Adversary attempting to access dormant accounts.
    0xC0000234 STATUS_ACCOUNT_LOCKED_OUT Account locked out due to threshold policy. Brute force triggered Active Directory account lockout.

    3. Incident Timeline & Attack Reconstruction¶

    By correlating event sequences across Azure Log Analytics, the attack was reconstructed chronologically:

    ```text [192.168.10.45] | | 14:02:11 - 14:14:05 UTC (142x Event 4625 | SubStatus 0xC000006A) +--------------------------------------------------------------------> [FIN-WKSTN-04] (SMB TCP 445) | Automated Dictionary Attack | | 14:14:28 UTC (1x Event 4624 | Logon Type 3) +--------------------------------------------------------------------> Password Guessed Successfully | | 14:15:10 UTC (Event 4688: cmd.exe -> whoami /all) +--------------------------------------------------------------------> Reconnaissance Execution

    // Microsoft Sentinel Scheduled Analytics Rule // Rule Name: Multiple Failed Logons Followed by Successful Logon (Potential Brute Force Compromise) // Severity: High | Tactics: Credential Access (TA0006) | Techniques: T1110.001 let timeRange = 1h; let failureThreshold = 10; let successWindow = 10m; let failedLogons = SecurityEvent | where TimeGenerated >= ago(timeRange) | where EventID == 4625 | where SubStatus == "0xc000006a" // Valid username, wrong password | where isnotempty(IpAddress) and IpAddress !in ("-", "127.0.0.1", "::1") | summarize FailureCount = count(), FirstFailure = min(TimeGenerated), LastFailure = max(TimeGenerated) by TargetAccount, IpAddress, Computer; let successfulLogons = SecurityEvent | where TimeGenerated >= ago(timeRange) | where EventID == 4624 | where isnotempty(IpAddress) and IpAddress !in ("-", "127.0.0.1", "::1") | project SuccessTime = TimeGenerated, TargetAccount, IpAddress, Computer, LogonType; failedLogons | where FailureCount >= failureThreshold | join kind=inner (successfulLogons) on TargetAccount, IpAddress, Computer | where SuccessTime between (LastFailure .. (LastFailure + successWindow)) | extend TimeDeltaSeconds = datetime_diff('second', SuccessTime, LastFailure) | project FirstFailure, LastFailure, SuccessTime, TimeDeltaSeconds, TargetAccount, VictimHost = Computer, AttackerIP = IpAddress, FailureCount, LogonType | order by SuccessTime desc
